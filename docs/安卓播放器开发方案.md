# Kikoeru 安卓播放器开发方案

版本：v0.1 · 日期：2026-09-05 · 状态：开发前方案

## 1. 产品定位与建议

开发一个连接自建 Kikoeru 服务器的原生安卓音声播放器。以作者 iOS 客户端的核心操作流程为功能参考，界面采用 Google Material 3，重点做好长音频、后台播放、目录播放和断点恢复。

建议使用 **Kotlin + Jetpack Compose + Material 3 + AndroidX Media3**。第一阶段不要求修改服务器，不使用 WebView 包装网页。先交付可日常使用的在线播放版本，随后加入离线下载、字幕和服务端状态互通。

默认决策：最低 Android 8.0（API 26）；手机优先，同时保留平板自适应布局；简体中文首发，字符串支持后续国际化；先交付可安装 APK。compileSdk、targetSdk 和依赖版本在开发启动时选择兼容的稳定版本并锁定，不在方案阶段臆定版本号。

## 2. 调研依据与边界

本方案核对了目标仓库当前公开的 `alpha` 分支路由、文件树生成逻辑，以及作者链接的 iOS 使用说明。当前工作目录为空，尚无应用代码。未连接真实服务器，未运行 iOS 客户端；本文的“已确认”指公开文档或源码可确认，不代表完成实际兼容性验证。开发前应固定后端 commit，并补充真实响应样本。

作者说明 iOS 客户端暂不开源，因此采用独立安卓实现。其公开说明确认的功能包括：服务器配置、可选账号认证、作品浏览与搜索筛选、详情和目录、音频播放、队列增删、迷你播放器；说明中明确当时未提供应用内睡眠定时。公开说明可能落后于实际版本，不能据此宣称完整复刻当前 iOS 功能。[iOS 使用说明](https://number17.online/docs/kikoeru-app/)

目标是兼容 Number178 分支，不默认承诺其他 Kikoeru 分支、第三方公共站点或全部历史版本兼容。[目标仓库](https://github.com/Number178/kikoeru-express)

## 3. 功能范围与优先级

P0 是首个可用版本；P1 是完整日用版本；P2 是后续增强。

| 功能 | P0 | P1 / P2 | 依据 |
|---|---|---|---|
| 服务器接入 | 地址校验、连接测试、匿名 / 账号登录、退出 | P1 多服务器切换 | iOS 已确认 |
| 作品库 | 分页、刷新、封面、标题、社团、声优 | P1 更多展示选项 | iOS 已确认 |
| 搜索筛选 | 关键词、排序、标签 / 社团 / 声优入口 | P1 高级组合搜索 | iOS 与后端 |
| 作品详情 | 元数据、可展开目录、文件时长 | P1 图片与文本查看 | iOS 已确认核心流程 |
| 播放 | 播放暂停、拖动进度、上下曲、快退 / 快进 | P1 A-B 循环 | 安卓产品设计 |
| 队列 | 当前目录播放、下一首播放、追加、移除、拖动排序 | P1 本地保存队列 | iOS 已确认增删，其余为增强 |
| 后台与系统控制 | 锁屏、通知、蓝牙耳机、音频焦点 | P2 Android Auto | 安卓核心要求 |
| 本地续播 | 曲目位置、队列与播放模式恢复 | P1 验证后接入服务器状态互通 | 安卓核心要求 |
| 睡眠与速度 | 15 / 30 / 60 分钟、自定义、当前曲结束；0.5–2.0 倍速 | P1 定时结束渐弱 | 安卓新增 |
| 我的记录 | 本地最近播放 | P1 服务端历史、收听标记、评分、短评 | 后端有相关路由 |
| 离线下载 | 暂不包含 | P1 单曲 / 目录、暂停续传、空间管理 | 安卓新增完整流程 |
| 字幕 | 暂不包含 | P1 LRC / SRT / VTT 展示与定位 | 后端提供查找入口 |
| 个性化 | 明暗主题、动态配色、快进间隔 | P1 封面配色和通知隐私模式 | 安卓新增 |

首版不包含服务器扫描管理、元数据抓取、账号管理、翻译任务创建、视频播放器、投屏、均衡器和跨平台客户端。此范围保证主要精力用于播放稳定性。

## 4. 信息架构与关键页面

底部三个入口：**作品、我的、设置**。搜索位于作品页顶部；“我的”承载最近播放，P1 再增加收听标记和下载。存在播放队列时，迷你播放器固定在底部导航上方。全屏播放器作为全局页面打开，不占一个底部入口。

### 4.1 首次接入

输入服务器地址 → 测试连接 → 判断是否需要登录 → 必要时输入用户名和密码 → 进入作品库。

地址示例允许域名、IP、端口和反向代理子路径；统一处理尾部斜杠。错误分别提示地址无效、连接超时、证书失败、账号错误、地址指向网页而非 API。保留输入便于修正。

### 4.2 作品库与搜索

顶部为标题、搜索入口和排序按钮，下方可显示已选筛选条件 Chip。手机采用两列封面卡片；窄屏或大字体允许单列。卡片仅显示关键元数据，避免把所有标签挤入列表。

搜索页展示输入框、最近搜索和结果；输入防抖建议 350 ms，取消旧请求，保证旧结果不会覆盖新关键词。筛选使用底部弹层，提供“重置”和“应用”；返回作品库保留滚动位置与筛选状态。

### 4.3 作品详情

封面与标题 → 社团 / 声优 / 标签 → “播放全部”或“继续播放” → 文件目录。描述可展开，目录保留层级和当前位置。文件行显示名称、时长、播放状态和更多菜单；非音频文件不会进入队列。

点击某曲目：用其所在目录的直接音频子项创建队列，从该曲目开始；“播放全部”按服务端目录顺序递归收集音频。存在不同语言、格式版本时不自动去重，用户可选择具体目录播放。更多菜单明确提供“下一首播放”和“加入队列”。

### 4.4 播放器

布局依次为收起按钮、封面、曲目名 / 作品名、进度条、已播放 / 总时长、快退 15 秒 / 播放暂停 / 快进 30 秒、上下曲、队列 / 倍速 / 定时 / 循环入口。较少使用的设置收进弹层，P1 字幕作为播放器内可切换视图。

播放模式支持顺序、单曲循环、列表循环和随机，默认顺序。定时器剩余时间可见，取消操作直接可达。点击迷你播放器展开；点击暂停仅暂停。返回键收起播放器并回到之前页面。

### 4.5 我的与设置

“我的”首版展示继续收听和最近播放；P1 分组显示服务端收听标记与已下载。“下载”明确展示等待、下载中、暂停、失败、完成，并支持重试和删除。

设置包括服务器、账号、主题、播放偏好、缓存容量和关于。切换服务器时停止当前网络播放并切换数据空间，避免新服务器凭据用于旧地址；离线数据按服务器与账号隔离。

## 5. Material 3 视觉规范

使用 Compose Material 3 组件与主题系统：NavigationBar、TopAppBar、SearchBar、Card、FilterChip、ModalBottomSheet、Slider 和 Snackbar。Android 12 及以上默认可跟随系统动态配色，旧版本使用固定种子色生成的明暗主题。[Material 3 官方说明](https://developer.android.com/develop/ui/compose/designsystems/material3)

以下为本项目设计取值：主色默认低饱和蓝色；页面水平边距 16 dp；卡片间距 12 dp；封面优先方形展示；卡片圆角 16 dp。使用系统字体，正文不小于 14 sp，主要按钮触控区域至少 48 dp。播放器主操作比辅助操作突出。

支持系统深色模式、字体缩放、TalkBack 标签、横屏及系统栏 Insets。选中和错误状态同时用文字 / 图标表达。长文件名允许展开或查看完整名称。加载、空库、无搜索结果、断网、失败重试分别设计状态，避免统一显示空白。

平板宽屏使用侧边导航与作品列表 / 详情双栏；播放器在宽屏采用封面和控制区并排。优先按可用窗口宽度自适应，而不是按设备型号判断。

## 6. 技术架构

采用单 Activity、Compose、ViewModel、StateFlow 和 Repository 分层；业务需要时抽出 UseCase，避免为简单读取增加多余层次。

| 层次 | 建议实现 | 职责 |
|---|---|---|
| UI | Compose + Material 3 | 页面、交互、可访问性 |
| 状态 | ViewModel + Coroutines / Flow | 页面状态、请求取消、用户事件 |
| 数据 | Retrofit + OkHttp + Kotlin Serialization | API、鉴权、错误归一化 |
| 本地 | Room + DataStore | 历史、队列、下载元数据与偏好 |
| 图片 | Coil | 封面加载、缓存与占位 |
| 播放 | Media3 ExoPlayer + MediaSessionService | 唯一播放器实例与后台会话 |
| 下载 | P1 Media3 DownloadManager / DownloadService | 下载生命周期和离线媒体 |
| 后台同步 | P1 WorkManager | 可延迟重试的状态同步 |
| 依赖注入 | Hilt | 统一服务与仓库生命周期 |

建议起步模块为 `app`、`core:data`、`core:playback`、`core:designsystem`，功能先按 package 组织。复杂度增长后再拆 feature 模块。

播放器和 MediaSession 由 Service 持有，页面通过 MediaController 观察和发出指令，保证切换页面或重建 Activity 不会重复创建播放器。前台媒体服务声明对应权限和 mediaPlayback 类型，系统媒体控制使用会话元数据。[后台播放官方文档](https://developer.android.com/media/media3/session/background-playback)

## 7. 后端接口对接

以下路径以 `/api` 为前缀。这里记录源码可见的接入面，完整 DTO、错误样本和参数契约在联调阶段补齐。

| 用途 | 方法与路径 | 接入要点 |
|---|---|---|
| 健康检查 | GET `/health` | 仅表示可达，不足以确认全部能力 |
| 登录 | POST `/auth/me` | JSON `name`、`password`，返回 `token` |
| 当前用户 | GET `/auth/me` | 无认证模式返回 `auth:false`；开启认证时无 token 可返回 401 |
| 作品列表 | GET `/works` | 分页与排序 |
| 搜索 | GET `/search` | `keyword`、`page`；高级搜索单独适配 |
| 详情 / 文件树 | GET `/work/:id`、`/tracks/:id` | 容忍可选字段缺失 |
| 封面 | GET `/cover/:id` | 可选 `type`，失败使用占位图 |
| 分类 | GET `/tags`、`/circles`、`/vas` | 对应 `/:id/works` 获取作品 |
| 媒体 | GET `/media/stream/:id/:index` | 优先使用文件树返回的媒体 URL |
| 下载 | GET `/media/download/:id/:index` | 同时兼容服务端返回的下载 URL |
| 字幕发现 | GET `/media/check-lrc/:id/:index` | 返回匹配结果、hash 和扩展名 |
| 评价与收听状态 | GET / PUT / DELETE `/review` | P1 接入，独立验证更新语义 |
| 历史 | GET / PUT / DELETE `/histroy` | 注意后端路径就是此拼写 |

路由依据：[挂载入口](https://github.com/Number178/kikoeru-express/blob/alpha/routes/index.js)、[认证](https://github.com/Number178/kikoeru-express/blob/alpha/routes/auth.js)、[作品接口](https://github.com/Number178/kikoeru-express/blob/alpha/routes/metadata.js)、[媒体接口](https://github.com/Number178/kikoeru-express/blob/alpha/routes/media.js)。

### 7.1 必须处理的兼容性细节

1. **鉴权统一**：API 支持 Bearer，也支持 query token；App 优先使用 Header，封面、音频和下载采用一致凭据策略。未发现本方案已核对路由中有 refresh token 接口，401 后进入重新登录流程，不无限重试。[鉴权中间件](https://github.com/Number178/kikoeru-express/blob/alpha/api.js)
2. **URL 与代理**：文件树可直接返回卸载媒体地址，媒体接口也可能 302。支持相对 / 绝对 URL、子路径代理及中文文件名；不跨来源转发服务器 Bearer token。开发时验证 URL 解析与 Range 请求链路。
3. **曲目身份**：`hash` 为 `作品ID/序号`，不是内容指纹。App 保存作品 ID、目录路径、文件名和最近服务器索引，重新加载文件树后再匹配。Linux 的目录字符串与 Windows 反斜杠差异需要样本验证；匹配不唯一时提示重新选择，不静默续播另一曲目。[文件树源码](https://github.com/Number178/kikoeru-express/blob/alpha/filesystem/utils.js)
4. **历史不等于既定同步协议**：历史写入接收 `work_id` 与任意 `state` 对象。现有客户端的 state 字段、时间单位、冲突规则尚未确认；P0 只写本地断点，P1 获得真实样本后再启用服务端写入，避免覆盖旧客户端状态。[历史路由](https://github.com/Number178/kikoeru-express/blob/alpha/routes/play_histroy.js)
5. **评价参数特殊性**：`starOnly` / `progressOnly` 的校验位置与实际读取位置存在 body / query 差异，适配层按实际实现和测试确定。收听标记使用服务端已有状态，不把“想听”误当成独立收藏系统。[评价路由](https://github.com/Number178/kikoeru-express/blob/alpha/routes/review.js)
6. **作品编号**：API ID 与界面显示编号分别保存，不能仅靠标题或强制 `RJ + 六位数字` 构造身份；BJ、VJ、自定义编号以目标部署实际返回为准。

## 8. 播放、缓存与恢复策略

播放状态统一为：空闲、准备、缓冲、播放、暂停、结束、失败。缓冲时保留曲目与进度，认证失败和格式不支持提供对应操作；瞬时网络失败做有限退避重试。

进入后台继续播放；耳机拔出暂停；音频焦点变化按语音内容场景处理，避免来电时竞争输出。用户主动暂停后不因网络恢复而自动播放。进程被终止后恢复队列和位置，默认等待用户播放，不承诺强制停止后自动启动。

建议每 10 秒及暂停、切曲、跳转完成时保存位置，单位统一为毫秒。作品收听标记和曲目毫秒位置分开存储。未知时长显示占位；不可 seek 的媒体不显示可用拖动能力。

首版格式验证集包括 MP3、AAC / M4A、FLAC、WAV、Ogg / Opus。实际支持取决于容器、编码和设备，不以扩展名承诺全部可播；第一版不引入 FFmpeg 解码扩展，先根据失败样本评估。[Media3 格式说明](https://developer.android.com/media/media3/exoplayer/supported-formats)

P0 可提供有容量上限的流式缓存；P1 将用户明确下载的文件与可淘汰缓存分开管理。离线目录保存媒体、必要元数据和可选字幕，飞行模式可独立播放。下载任务记录服务器、账号、曲目匹配信息和完成状态；只有完整校验后显示完成。Range 不可用时不伪装续传，明确重新下载。删除缓存不删除用户下载。[Media3 下载文档](https://developer.android.com/media/media3/exoplayer/downloading-media)

本地建议实体：ServerProfile、WorkCache、TrackReference、PlaybackCheckpoint、QueueEntry、DownloadEntry。所有账户相关主键包含 serverId 和 accountId；token 使用 Android Keystore 保护的加密存储，不保存明文密码，不写日志。

HTTPS 为默认接入方式；兼容用户自建 HTTP 服务需显式提供服务器级选项，记录为用户选择。不得通过信任所有证书实现 HTTPS 兼容。下载优先使用应用专属目录，导出时使用系统文件选择机制。

## 9. 开发里程碑与交付

以下是单名熟悉安卓开发者的初步有效工作日估算，包含基础验证；真实后端差异与设备兼容问题可能增加时间。

| 阶段 | 工作内容 | 预计 | 完成条件 |
|---|---|---|---|
| M0 接口验证 | 固定后端版本、认证、文件树、播放 URL、Range、格式样本 | 2–3 天 | 登录与拖动播放链路验证通过 |
| M1 基础应用 | 工程、主题、连接页、作品库、搜索、详情 | 4–6 天 | 可连续浏览并选择音轨 |

| M4 日用增强 | 下载、字幕、历史与评价联调、多服务器 | 7–10 天 | P1 验收通过 |

P0 合计约 14–20 个工作日；P1 另需约 7–10 个工作日。交付物包括源码、安装 APK、接口适配说明、已测设备 / 服务器矩阵与已知限制。签名密钥由项目持有者管理，不进入仓库。

## 10. 验收标准

| 场景 | 通过标准 |
|---|---|
| 接入 | 认证开 / 关均可使用；错误凭据、超时与证书失败可区分 |
| 浏览 | 翻页不重复、不漏页；快速修改搜索时结果不串台 |
| 文件目录 | 多层目录、中文 / 日文、重名文件可正确定位；非音频不入队 |
| 连续播放 | 指定真机锁屏连续播放 60 分钟，至少完成一次自动切曲，无应用自身导致中断 |
| 系统控制 | 锁屏 / 通知 / 耳机控制与 App 状态一致；耳机断开暂停 |
| 续播 | 正常暂停恢复误差目标 ≤ 2 秒；突发进程终止丢失位置目标 ≤ 10 秒 |
| 网络 | 断网与 401 不死循环；代理重定向后可播放；支持 Range 的部署可跳转 |
| 文件变化 | 增删文件后不会仅按旧索引播放错误曲目；无法匹配时提示 |
| 首播性能 | 在固定中端真机、局域网、指定 MP3 样本下，点击至出声 P95 目标 ≤ 2 秒，记录至少 30 次 |
| UI | 明暗主题、大字体、TalkBack、窄屏与平板无主要操作遮挡 |
| P1 离线 | 飞行模式播放已下载内容；任务中断后恢复；空间不足有明确提示 |
| P1 同步 | 样本确认 state 契约后测试多端轮流续播，失败写入不丢本地进度 |

自动化测试聚焦 URL 解析、鉴权隔离、曲目匹配、队列操作、DTO 容错和断点恢复；集成测试覆盖真实后端与代理；后台音频和蓝牙在真机验证。首版至少覆盖 API 26、一台较新原生 Android 设备及一台常见定制系统设备。

## 11. 开发前仍需补齐的信息

这些信息不阻碍本方案成立，但会影响联调结果：实际服务器版本与部署方式、是否启用认证 / 子路径代理 / offloadMedia、典型音频格式、是否需要兼容其他分支，以及 iOS 最新版是否存在公开说明之外的关键功能。

建议下一步先进行 M0：用目标服务器验证认证、目录与可拖动音频流，同时制作作品库、详情、全屏播放器三张 Material 3 页面原型。验证通过后按本方案进入 P0 开发。
