# 接口与验证记录

后端基线：[Number178/kikoeru-express，commit 6a7568ac869b5658c6da898acbafa1bfce135b0a](https://github.com/Number178/kikoeru-express/tree/6a7568ac869b5658c6da898acbafa1bfce135b0a)，调研日期 2026-09-05。

本客户端独立实现协议适配，未复制后端或 iOS 客户端实现代码。

## 已采用的协议

- 登录：POST `/api/auth/me`，body 为 `name`、`password`，返回 `token`。匿名认证检测使用 GET 同路径，401 时展示账号表单。
- 列表：GET `/api/works`；搜索：GET `/api/search?keyword=...`；使用服务端 `pagination.totalCount`，不假设固定页长。
- 分类：GET `/api/{tags|circles|vas}/{id}/works`。
- 详情：GET `/api/work/{id}`；文件树：GET `/api/tracks/{id}`。
- 曲目类型通过 `type` 判定，音频才入队。时间由秒转换为毫秒。作品元数据的缺省可选字段有默认值。
- 文件树 `hash` 不是稳定内容哈希；播放和恢复前根据作品 ID、目录路径、文件名重新获取当前索引。
- Header 鉴权使用同源且属于配置路径范围的请求；跨源重定向移除 Authorization；HTTP 仅用于明确允许的服务器主机和端口。
- 应用不会写入服务端 `/histroy` 与 `/review`，这些是 P1 范围。当前断点和队列只保存在本机 Room 数据库。

## 自动化验证设计

`ServerUrlsTest`：代理前缀、根路径与绝对媒体地址、中文编码、HTTP 许可、内嵌凭据拒绝。

`TrackMatchingTest`：目录展开、非音频排除、文件序号变化、文件删除、重名歧义、账号隔离、JSON 字段容错。

`NetworkTest`：真实本机 HTTP/HTTPS 测试服务器验证 Bearer、Range、跨源重定向、路径范围隔离及搜索参数。

`scripts/fixture-server.py`：提供合成作品、目录、90 秒极低音量测试 WAV 和 Range 响应，可选择启用测试账号。它只用于开发验证，不包含真实音声资源，不代表目标服务器部署已通过联调。

## 0.2.0 本地及 AI 字幕（2026-09-06）

### 协议与行为

- 本地字幕通过 `/api/tracks/{id}` 文件树发现，使用文件节点的 `mediaStreamUrl` 读取，支持代理子路径与既有账号请求策略。优先匹配同目录 `音轨名.lrc`、`音轨名.mp3.lrc` 等同名规则，其余作品内字幕可手动选择。
- AI 任务通过 GET `/api/lyric/translate?page=-1&work_id={id}&status=[]` 查询，以作品 ID 和规范化完整音轨路径精确匹配。状态 1 等待、2 生成中、3 成功、4 失败；仅成功任务可选择。
- 成功任务通过 GET `/api/lyric/translate/lrc?id={taskId}` 的 `lrcContent` 读取。本轮只读取既有字幕，未提交、修改或删除服务端生成任务。
- 协议依据：[本地媒体路由](https://github.com/Number178/kikoeru-express/blob/alpha/routes/media.js)、[AI 字幕路由](https://github.com/Number178/kikoeru-express/blob/alpha/routes/translate.js)、[文件树](https://github.com/Number178/kikoeru-express/blob/alpha/filesystem/utils.js)。
- 支持 LRC 多时间标签、双语同时间合并、文件 offset；SRT/VTT 多行、重叠与空档；ASS/SSA Dialogue 文本时间轴。ASS 特效和定位不渲染。
- 播放器封面区域显示同步字幕，高亮当前句，支持自动跟随、点击跳转、手动来源选择、字幕开关和 ±30 秒时间调整。字幕开关持久保存，来源与偏移在本次应用运行期间按音轨和字幕分别记忆。
- 切歌或换账号取消旧下载；字幕加载失败不影响音频播放，AI 接口缺失不会屏蔽本地字幕。读取上限 2 MB，解析上限 20000 条；编码使用 BOM / 服务端声明 / UTF-8，无法识别时显示错误提示。
